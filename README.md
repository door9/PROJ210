# PROJ210

매매의 **결과**가 아니라 **판단**을 기록하고, 시간이 지난 뒤 그 판단을 채점하는 개인 투자 복기 앱.
"내 계좌를 하나의 펀드로 보고, 나는 그 펀드의 매니저이자 유일한 고객"이라는 관점으로 만들었다.

## 기능

| 기능 | 설명 |
|---|---|
| 매매 기록 | 매수 시 이유·미리 정한 매도 조건·감정을 기록. 매도 시 "살 때의 나"가 다시 나타나 대조 |
| 만약 | 실제의 나 vs 코스피만 / S&P500만 / 코카콜라만 / 예금만 산 나 — 같은 날 같은 금액을 굴린 다섯 세계의 현재 가치 비교 |
| 회상 | 매도(판 뒤 그 주식이 어떻게 됐나)와 물타기(그 돈을 지수에 넣었다면)를 채점. 종목 중복 없이 상·하위 5건씩 보여주고 전체는 버튼으로 |
| 홀딩 일지 | "팔고 싶다/더 사고 싶다" 순간을 기록 → 몇 달 뒤 그 감정이 신호였는지 소음이었는지 채점 |
| 투자 헌법 | 원칙을 조문화(비중 한도·최소 보유일·물타기 금지는 자동 감시). 위반 시 경고하되 기록은 막지 않음 |
| 주주 서한 | 분기마다 나에게 쓰는 운용보고서. 수익률·벤치마크·거래·위반·지난 서한을 자동 요약으로 차려줌 |
| 관심 종목 | 사지 않은 판단의 기록. 샀다면 수익률, 안목 점수, 교체 시뮬레이션 |
| 기간 수익률 | 주/월/연 단위 시간가중수익률(TWR) |
| 투자 비용 | 대출 계좌별 이자를 계산해 이자 차감 후 실질 손익을 보여줌 |
| 2ⁿ | 펀드를 청산해 세대별로 보관하고 빈 장부로 다시 시작 |
| AI 복기 | 기록 전체 + 심문 프롬프트를 데이터 팩으로 복사 → 원하는 AI에 붙여넣어 행동 패턴을 심문받기 |

## 구조 (개인정보 보호가 설계 기준)

- 바닐라 JS PWA (빌드 없음). **이 공개 저장소에는 앱 코드만 있다** — 매매 기록·종목명 등 개인 데이터는 없음.
- 사용자 데이터(매매·일지·헌법·서한·현금 입력 등): 브라우저 localStorage + **본인 Dropbox**(전용 앱 폴더의 `data.json`) 동기화.
  기기 간 병합은 항목별 `updatedAt` 엄격 비교(로컬이 확실히 새것일 때만 로컬 우선) + 삭제 tombstone.
  **`settings`만은 통째로 병합된다**(마지막에 저장한 기기가 이긴다) — 그래서 **여러 줄이 쌓이는 기록을 settings에 두면 안 된다.**
  한때 현금 입력(`cashLog`)이 거기 있었고, 두 기기에서 입력하면 늦게 저장한 쪽이 상대 입력을 통째로 지웠다.
- 백업 내보내기(설정 → JSON 파일로 내보내기)에는 **GitHub 토큰과 앱 잠금 PIN이 들어가지 않는다.**
  가져올 때는 그 두 값만 지금 기기 것을 유지한다.
- 시세·종목 목록: **비공개 저장소**(PROJ210-data)에 보관. 앱은 개인 접근 토큰(PAT)으로 GitHub API를 통해 읽고,
  새 종목 기록 시 tickers.json 커밋 + 갱신 워크플로 실행까지 자동.

### 시세가 들어오는 길

앱은 시세를 **읽기만 한다.** 수집은 서버에서 하고, 방아쇠가 세 겹이다.

1. **서버 크론(주 경로)** — 항상 켜져 있는 개인 서버가 각 시장 마감 직후 GitHub Actions를 호출한다.
   정시에 돈다.
2. **GitHub Actions 예약(백업)** — 평일 18회. 예약 자체가 몇 시간씩 늦게 배달되는 일이 잦아 주 경로로는 못 쓴다.
3. **앱의 자가 치유** — 앱을 열었는데 오늘 종가가 아직 없으면 한 번만 갱신을 요청한다(기기·시장·날짜당 1회).

수집은 `PROJ210-data`의 `scripts/fetch_prices.py`가 한다. 마감·휴장일 판정과 휴장일 캘린더도 거기 있다
(**앱이 아니라 그 파일에서 매년 갱신**). 종목은 동시에 받는다 — 한국 6초, 미국 9초, 전체 11초 안팎.
보관 구간은 `KEEP_FROM`부터다(앱이 조회할 수 있는 가장 이른 날짜보다 앞이면 충분하며, 더 이른 매매를 넣게 되면 내려야 한다).

앱 쪽은 받은 시세를 **IndexedDB에 캐시**하고, 열 때는 캐시로 즉시 그린 뒤 뒤에서 `meta.json` 하나만 확인해
**지문이 달라진 종목만** 받는다. 첫 화면이 홈이면 보유 종목과 환율만 먼저 읽는다.

- 로컬 개발: `data/` 폴더가 있으면 폴백으로 사용(.gitignore 처리, `python scripts/fetch_prices.py 심볼`로 생성).

### 회계 가정 (engine.js)

- **투입 원금 = 밖에서 새로 끌어온 돈만.** 매수는 같은 통화의 매도 대금(pool)으로 먼저 충당하고 나머지가 새 돈이다.
  입출금·환전·배당·현금 입력을 모두 추적한다(`capitalLedger`).
- 같은 날 사건 순서는 **입금 → 매도 → 환전 → 매수 → 출금 → 현금 잔액 입력**. 돈이 생기는 일이 먼저다.
- 배당·이자·대여료는 **수익이지 자본이 아니다** — 현금만 늘리고 원금은 안 늘린다.
- 수익률 = (평가 + 뺀 돈 − 넣은 돈) ÷ 순투입. 기간 수익률은 시간가중(TWR).
- 평가액 = 매수원가 × 수정종가 성장배수 → 배당 재투자·액면분할 자동 반영.
- 통화별로 따로 집계하고(원화 슬리브·달러 슬리브), 합산할 때만 현재 환율로 환산한다.
- 다섯 평행우주 모두 같은 자금 흐름을 쓴다 → 비교는 공정.

### 검사

```
python -m http.server 8735 --directory .
# 브라우저에서 http://localhost:8735/tests/test.html
```

`tests/`는 **지어낸 장부**로 회계 불변식을 확인한다(개인 기록을 쓰지 않는다). 개발일지에서 실제로 터졌던
사고들 — 같은 날 순서 뒤엉킴, 배당 이중 계상, 출금이 분모를 깎는 문제, 기기 간 현금 입력 유실 등 — 을 그대로 시험으로 굳혔다.
**회계 쪽을 건드리면 여기부터 초록인지 볼 것.**
